实现行为
1. policy 的正式注册名为 WSA_1_5，Python 包为 lerobot.policies.wsa1_5。
   dataset 的正式注册名为 wsa1_5。复用现有 draccus CLI、factory、DataLoader、
   数据混合/权重采样、Accelerate、optimizer/scheduler、日志和 checkpoint 体系。
2. 数据 adapter 组合现有 LeRobotDataset，使用实际 frame table 的 timestamp。
   未来索引按 frame_stride 采样，允许跨子任务；复用 LeRobot 的 episode 尾部 padding/mask。
   仅越过 episode 末尾时重复末帧；当前子任务仍决定文本条件和 3D 终点标签。
   重复出的越界帧明确标记无效；每条 future_rgb/future_motion 仍为 32 时间步。
   Motion 视频帧按与 RGB 相同的源 timestamp 查询；不臆造其物理单位或编码 scale。
3. 已核实 sidecar 为 episode 对象列表，字段为 episode_index/task_instruction/scene/
   subtasks；子任务使用 subtask_id/subtask_text/start_frame/end_frame/hand_used。
   hand_used 0/1/2 映射左/右/双手，不使用 object_rigidity/object_ragidity。
   缺标注、null 字段或非法边界清空对应文本；未标注区间 subtask_id=-1，
   metadata_valid=false，3D endpoint 监督被屏蔽，不伪造“真实子任务结束”。
4. 三视角按配置/schema 的 image0/image1/image2 顺序拼接：上方 256x320，
   下方左/右各 128x160，最终画布 [C,H,W]=[3,384,320]。
   Motion resize 为 [3,192,160]。RGB/Motion 都使用显式 ImageNet 归一化。
   缺失媒体及解码失败使用带 mask 的占位；推理也屏蔽无效 RGB 视角和 3D queries。
5. observed_rgb、condition_text 为条件；future_rgb、future_motion、goal_rgb_views
   放在 targets 中。goal_rgb_views 保留每路原始图像尺寸和 [0,1] 数值。
   build_inference_condition 与 predict_future 的签名不接受 motion 或 GT target。
6. CausalMoT 保留每个专家的 Q/K/V、FFN、modulation 和 RoPE，允许不同 hidden width，
   但所有专家共享 attention head geometry 和层数。O 中包括当前 RGB 与文本 tokens。
   Query->Key 依赖为 O->O；R->O,R；M->O,M；G->O,R,M,G。
   生产实现按允许的 key group 汇集；SDPA、math、reference 后端都保留显式 mask。
   padding key 不可见，全空 attention 行有安全 softmax 和严格零输出。
7. RGB/Motion 使用独立 Wan-style Transformer 参数。RGB 从完整 Wan 权重初始化；
   Motion 与 3D backbone 通过显式逐轴插值缩宽，time_projection 的六组门控不混合。
   加载前报告 missing/unexpected/shape mismatch，并记录各层参数数量；没有随机回退。
8. 33 帧 RGB=当前 1 帧+未来 32 帧；Motion=固定模型域零占位帧+未来 32 帧。
   RGB 训练复用完整干净视频的首帧 latent；推理或无 RGB target 时单独编码观测。
   Motion placeholder 保留 codec 时间布局，但其 token 在 MoT 前移除，不参与注意力或监督。
   明确校验 Wan 的 9 latent 时间步及 33 decoded 帧；仅未来 latent 参与 flow loss。
   官方源码显示直接编码 32 帧会得到 8 latents、解码 29 帧，真实权重行为待服务器验证。
9. Future3DExpert 使用 819 个随机初始化的可学习 queries，每视角 1 camera +
   16 register + 256 patch。四层 feature heads 输出 [B,3,273,2048]。
   默认 teacher 层 [4,11,17,23] 对应 30 层 student 的 [5,14,21,29]。
10. Omega 的特殊 token 起始为 17；patch 数随 max_size=256 的实际网格变化。
    原始图像遵循官方中心裁剪、PIL bicubic resize 和多视角白色 padding；没有拉伸成
    固定正方形。17 个特殊 tokens 直接对应，patch features 按内容区域网格采样至 16x16。
    padding/缺失视角不参与 normalized feature MSE 与 cosine feature loss。
11. enable_3d_queries 控制 G，enable_3d_supervision 控制监督，lambda_3d=0 也关闭监督。
    监督关闭时不构造 OmegaTeacher，不要求目标图像、不读取 teacher 缓存、不计算 3D loss；
    G 可保留参与联合前向并输出特征，但无监督的 3D 参数冻结并移出优化器。
    factory 同时关闭 dataset 的终点图像/goal mask 加载；collate 支持不含 3D 标签的 batch。
    采样 helper 的 return_features 只决定返回值，不再决定已初始化的 G 是否参加每步联合前向。
    OmegaTeacher 仅在监督有效时创建，冻结/eval/inference_mode，训练 target extraction 才懒加载。
    不注册为 policy 子模块，teacher 权重不进入 policy checkpoint。懒初始化保护 RNG，
    有无 endpoint 标签不能改变 student 的随机噪声轨迹。推理不加载或调用 teacher。
12. 按用户最新澄清，O/R/M/G 在同一次 MoT 前向中联合计算。
    训练时 R/M 使用标准 flow matching 带噪状态，G 从同次前向的隐藏表征预测几何特征。
    不额外采样未来或执行第二次 feature pass；推理时每一步去噪也联合计算 G。
    目标图像和 teacher features 仅作监督，不输入学生；3D 输出取最后一次联合前向。
    goal_sampler_steps 仅为旧 checkpoint 字段，不再控制训练计算；goal_conditioning 为 joint。
13. 总损失为 lambda_rgb*RGB flow + lambda_motion*Motion flow + lambda_3d*3D feature。
    各项单独日志；支持 modality enable、模块冻结、四类独立学习率参数组。
    默认训练参数保持 FP32，计算使用 BF16 autocast；冻结 VAE/UMT5 按计算 dtype 加载。
    同时修正 RMSNorm 的 dtype promotion，确保异宽 MoT 的 Q/K/V dtype 一致。
14. gradient accumulation 接入现有 trainer，不增加完整 trainer。只有 sync_gradients
    时 clipping/optimizer/scheduler/zero_grad；WSA 检查非有限 loss/gradients。
    effective batch size 包含 accumulation。其他 policy 默认仍按原有单步路径运行。
15. 可选缓存包含 UMT5 embeddings、VAE latents、Omega endpoint features。
    缓存按样本/endpoint 寻址，跨 batch size、shuffle、worker 与数据混合可复用。
    identity 包含真实输入内容、权重 SHA256、dtype、prompt/sidecar、preprocessing 版本。
    文件采用 safetensors 与原子写入；冻结资产 identity 随 policy config 保存，支持
    resume 后继续使用缓存；tokenizer 与训练 teacher 的资产仍按实际文件校验。
